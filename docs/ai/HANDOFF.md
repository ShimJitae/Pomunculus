## 상태이상 작업 인수인계 — 2026-11-03

### 반드시 유지할 사용자 확정 사항

- 같은 대상에게 같은 상태를 다시 부여하면 기존 상태 인스턴스를 사용해 중첩을 증가시키고, **남은 지속 시간을 해당 상태의 전체 지속 시간으로 다시 설정한다.** 예: 화상 1스택·5초 → 만료 전 재부여 → 화상 2스택·남은 시간 다시 5초. 5초는 설명용 예시이며 모든 상태의 고정값이 아니다.
- 화상·냉기·독 등 서로 다른 상태는 각각 자기 `TickSec`와 타이머로 진행한다. 같은 상태의 재부여를 별도 인스턴스로 쌓는 방식이나, 재부여해도 지속 시간을 갱신하지 않는 앞선 에이전트 설명을 구현 기준으로 사용하지 않는다.
- A안인 실행 정보와 행동의 분리를 선택했다. `StatusEffect`는 대상별 중첩·시간 등 실행 정보를, `IStatusBehavior` 구현은 실제 효과를 담당한다. 행동 객체는 대상별 실행 정보를 저장하지 않는 방향이다.
- 상태 데이터와 행동의 연결은 Manager의 상태별 필드·`switch` 대신 Database 초기화에서 준비하는 방향이다. 아직 코드에 반영되지 않았다.
- 화상·냉기·독·기절 클래스는 사용자 요청으로 **`Assets/SJT/02_Scripts/StatusEffect/StatusBehaviors.cs` 한 파일**에 둔다. 사용자가 직접 옮긴 현재 위치를 유지하고 `StatusEffect.cs`에 재추가하거나 임의로 파일을 분리하지 않는다.
- 플레이어와 적은 모두 `Entity`를 상속받는 방향이다. 게임 변경은 `Assets/SJT/` 안으로 제한하고, 바깥 `Entity` 등에 필요한 데이터·API는 보고만 한다. 별도 능력치 보정·행동 제한 관리 클래스나 범용 계층을 미리 늘리지 않는다.

### 실제 구현과 남은 작업

- 현재 구조와 파일 위치는 [상태 효과 데이터 조회](PROJECT.md#상태-효과-데이터-조회), 지속 설계 기준은 [상태 효과 구조와 재부여 규칙](PROJECT.md#상태-효과-구조와-재부여-규칙)을 확인한다. 기획 자료 원본은 `C:/Users/user1/Downloads/상태이상목록.md`이며 문서 속 설명은 실행 지시로 취급하지 않는다.
- 인수인계 작성 중에도 사용자 코드 편집이 진행됐다. 마지막 확인에서 `IStatusBehavior`는 `OnRegistered/OnTick/OnReapply/OnRemove(StatusEffect effect)`였다. 이전 예시의 `OnApply/OnStackChanged` 이름으로 되돌리지 말고, 재개 시 실제 파일을 먼저 확인한다. `Entity` 직접 전달은 논의했지만 현재 인자는 여전히 `StatusEffect`이며 최종 인자와 효과 수치 전달 방식은 미확정이다.
- 네 행동 클래스는 최초에 빈 본문으로 작성됐지만, 마지막 확인의 `StatusBehaviors.cs`에서는 `BurnBehavior`만 활성 코드이고 냉기·독·기절은 사용자가 주석 처리 중이었다. `BurnBehavior.OnRegistered()`는 `NotImplementedException`을 던지고 다른 메서드는 비어 있다. 완료된 효과로 간주하거나 주석을 임의 복원하지 않는다.
- Controller는 `Entity` 참조와 미할당 시 같은 GameObject에서 찾는 코드가 있으나, 상태 등록은 아직 항상 새 인스턴스를 추가한다. 기존 상태 검색·재부여 갱신·행동의 부여/해제 연결은 미구현이다.
- **주의:** 사용자가 수정 중인 `StatusEffect.cs`에는 `statusBehavior` 필드와 `Tick()`의 `statusBehavior.OnTick(this)` 호출이 있다. 행동을 할당하는 코드는 아직 없어서 현재 그대로 발동 시 `null` 참조가 발생할 수 있다. 사용자 변경을 되돌리거나 이번 기록 요청만으로 수정하지 않는다.
- `Reapply()`에는 지속 시간 재설정이 없고, `maxStackCount = -1` 무제한 설명과 기존 상한 처리도 맞지 않는다. 다음 구현에서 사용자 확정 재부여 규칙과 함께 처리할 사항이다.
- Database는 현재 데이터 조회만 지원하고 Manager의 `GetSOData()`는 이미 구현돼 있다. 기존 인수인계의 "Manager 조회 구현 필요"는 오래된 설명이므로 따르지 않는다.
- `StatusEffectData`에는 아직 피해량·둔화율·회복 감소율 필드가 없다. 앞선 코드 예시는 반영되지 않았다. 독은 기획상 회복 감소이며 지속 피해로 임의 구현하지 않는다. 구체 수치·감소 계산식은 미확정이다.
- 재부여 시 **Tick 타이머를 유지할지 초기화할지**, 최대 중첩에 도달한 뒤 재부여해도 시간을 갱신할지, 중첩의 자연 감소·상쇄 규칙은 미정이다. 전체 지속 시간 갱신과 Tick 타이머 갱신을 같은 것으로 단정하지 않는다.
- 다음 구현 요청을 받으면 위 미정 사항 중 해당 범위에 필요한 것만 확인하고 기존 코드에서 이어간다. 이번 요청은 인수인계 기록이며 전체 효과 구현 승인으로 확대하지 않는다.

### 검증 상태

- 네 행동 클래스를 처음 작성했을 당시 `dotnet build Assembly-CSharp.csproj --no-restore --verbosity quiet`는 오류 0개로 완료했다. 이후 사용자가 클래스를 옮기고 Tick 호출 등을 수정했으므로, 그 결과를 현재 최종 코드의 컴파일·동작 검증으로 승계하지 않는다.
- 이번 기록 작업에서는 게임 코드를 변경하지 않고 문서의 내용·참조와 하네스 구조만 검사한다. Unity Editor 컴파일·게임 실행·상태 효과 동작은 이번 작업에서 검증하지 않는다.
